# Security Audit

Earlier rounds: `docs/audit/SECURITY_REPORT.md` (S-01 … S-24, all fixed or owner items). This file adds round 8 and
the current state of each requirement.

## Requirement checklist (current code, 5 Nov 2026)
| Requirement | Status | How it is enforced / evidence |
|---|---|---|
| Customers see only their own data | Fixed earlier, re-verified | RLS on every table; `asUser()` runs customer queries as `authenticated` with `auth.uid()`; `test/rls-isolation` |
| Customers cannot change payment status / prices | Verified | Order totals computed on the server (`buildQuote`); client prices ignored (`race.py` "server ignores client prices"); payment status only via admin routes / signed webhooks |
| Admin-only operations checked on the server | Verified | Every `/api/admin/*` handler calls `requireStaff()` / `requireAdmin()`; live: 14 admin APIs → 401 without a session |
| No service-role key in the browser | Verified | `SUPABASE_SERVICE_ROLE_KEY` read only in `lib/env.ts` (server-only module); not `NEXT_PUBLIC_*` |
| SQL injection | Verified | All queries parameterised (`$1…`); no string-built SQL with user input |
| SECURITY DEFINER functions | Verified | All set `search_path = public`; execute revoked from `public/anon` where not needed; new `log_stock_movement` is a trigger function with execute revoked |
| CSRF | Verified | Proxy rejects cross-site Origin on mutating `/api/*` (403) |
| Secure session cookies | **Fixed (R8-07)** | `Secure` on https; `SameSite=Lax`; HSTS header present |
| OTP: random, expiring, single-use, rate-limited | Verified | Codes generated by Supabase Auth (`generateLink`), verified by Supabase (`verifyOtp`); app rate limits per address and per network (`api/auth/email`); resend replaces the old code |
| Redirect URLs validated | Verified | `safeNextPath()` for every `next=`; auth error redirects carry only the validated `next` |
| Payment verification server-side | Verified | Razorpay signature (HMAC) + amount + currency checked; duplicate webhook events ignored (event id); UPI UTR unique |
| Secrets not in repo / logs | Verified | Only `.env.example` files tracked; secret pattern scan clean; OTP values and passwords never logged; audit log redacts password/token/otp/secret keys |
| Dependencies | Verified | `npm audit --omit=dev`: 0 vulnerabilities (4 Nov). Expo tooling advisories (dev-only) remain — see below |
| Admin audit trail | **Fixed (R8-08)** | `admin_audit_log`, admins read only |
| Stock history | **Fixed (R8-09)** | `stock_movements`, staff read only |
| Security headers / CSP | Verified live | HSTS, CSP (no `unsafe-eval`), X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy; `x-powered-by` hidden |
| `.env` / `.git` not served | Verified live | 404 |

## Potential risks / external
| Item | Type | Detail |
|---|---|---|
| Preview deployments use the production database | Potential risk | Vercel preview builds share `POSTGRES_URL`; they never migrate (script skips), but someone testing on a preview URL writes real rows. Vercel "Standard Protection" keeps previews behind Vercel login by default — keep it on. Better: a Supabase branch database for previews |
| Razorpay manual capture (R8-11) | Potential risk | Only when online payments are enabled |
| Guest WhatsApp orders (OPEN-11) | Potential risk | Abuse can hold stock 12 h; owner to set a size cap |
| Expo tooling advisories | Potential risk (dev-only) | 17 advisories in build tooling (not shipped in the app); fixed by the next Expo SDK upgrade |
| Login CSRF confirm step, DB TLS CA pinning, SecureStore for the app session | Potential risk (low) | Listed earlier (S-series); not changed |
| Vercel/Supabase/Hostinger/Gmail account security | External | Owner: 2-step verification on every account |

## Security status
No open Critical or High security issue in the code. Remaining items are configuration (previews DB, Razorpay
capture mode before enabling payments) and owner decisions.
